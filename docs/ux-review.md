# UX 评估与设计约定

保留侧栏、搜索、卡片／列表和详情抽屉，借鉴文件管理器的范围选择与属性查看习惯。减少噪声，不新增看板或评分。

## 已落地

1. **先看自己的 Skills**：个人范围默认，记住选择；分类、收藏、归档和快速查找使用同一口径。空结果提供查看全部来源的入口。
2. **详情先回答用途和调用**：名称、描述、来源状态和真实 `$` 调用位于编辑表单之前；保留设置短名与已有键盘习惯。
3. **状态准确**：区分入口未创建、入口未找到、入口待核对和入口已创建；不把缓存显示成已启用，不把单文件导入显示成完整安装。
4. **整理直达对象**：正常兼容关系单独呈现；同名、正文一致、引用与版本记录变化用事实命名，操作定位实际涉及的 Skill。

## 文案

使用「复制调用」「待核对」「查看来源」「更新版本记录」等直接动词。只有必要限制保留短提示，不添加口号、解释性横幅或虚构推荐理由。

## 后续

用已有分类积累场景首选，再考虑更复杂的任务匹配。持续检查次级文字对比、长名称、窄屏换行和键盘焦点。减少内容不应降低可读性。

## 验证

使用 `npm run demo` 的隔离数据做 UI 验证与公开截图。源码检查、模拟 DOM、HTTP 检查和真实浏览器结果分别报告，避免把它们混为同一种验证。
