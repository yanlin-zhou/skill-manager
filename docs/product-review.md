# 产品评估与路线

目标：Skill 很多时，用户仍能判断「我有哪些、这次用哪个、调用什么、哪些关系或版本需要处理」。

## v0.3 已落地

1. **范围先行**：默认个人 Skills，插件缓存、系统项与全部来源明确切换；列表、分类、收藏、归档和快速查找保持同一范围。
2. **先使用，再编辑**：详情先展示用途与可信调用入口。仅保存的短名不是已安装入口；缓存和单个导入文件也不是完整安装证据。
3. **按证据整理**：正文相同、同名来源、缺失引用和版本记录变化分别表达；正常兼容关系不作为冲突。操作直接定位相关 Skill 或依赖。

## 下一步

### 场景首选

在已有分类与收藏中建立用户明确选择的常用入口。匹配依据应来自描述、备注和用户选择，而非将固定排序包装成个性化推荐。

验收：同一场景能快速找到自己确认的首选；无匹配依据时不凑推荐；兼容入口不会挤占同一目标的位置。

### 可核对的上游版本

先记录仓库、安装引用和本地版本，再提供只读核对。至少区分未检查、无法检查、已核对和发现新版本，显示检查时间及来源。

验收：只有取得可比较的上游证据才显示可更新。没有版本、没有来源或网络失败保持未知。Skill、插件包、应用自身版本和手动依赖记录分别处理。

## 产品边界

文件引用不等同必需依赖；同名不等于实际调用冲突；无手动记录不等于未使用。更新前应先解决来源、本地改动及恢复方案，不做无证据的自动升级、删除或合并。
